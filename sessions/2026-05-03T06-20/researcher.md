# 📋 프로젝트 관리 표준 데이터 구조 제안

본 구조는 **프로젝트별 상세 기록 시트** 또는 **중앙 관리 대시보드(DB/스프레드시트)**의 기본 필드가 되어야 합니다.

## 1. 핵심 엔티티 정의 (Project Entity)

모든 프로젝트 항목은 다음의 필수 정보들을 포함해야 합니다.

| 필드명 (Field Name) | 데이터 타입 | 설명 (Description) | 예시 (Example) | 비고 (Notes) |
| :--- | :--- | :--- | :--- | :--- |
| **Project ID** | String/Auto-ID | 프로젝트 고유 식별 번호 | P-20240503-001 | 시스템 추적을 위해 필수 |
| **프로젝트 명** | Text | 프로젝트의 구체적인 명칭 | 장비견적 요청 (OMR) | 명확하고 구체적으로 작성 |
| **프로젝트 유형** | Select/Enum | 프로젝트의 대분류 | 장비/시설, 인테리어, 비딩, 아카데미 등 | 분류 용이성 확보 |
| **상태 (Status)** | Select/Enum | 현재 프로젝트의 진행 상태 | To Do, 진행 중, 검토 요청, 보류, 완료 | 핵심 지표 |
| **우선순위** | Select/Enum | 프로젝트가 회사 목표에 미치는 중요도 | 최우선, 높음, 보통, 낮음 | 자원 배분 기준 |
| **담당자 (Owner)** | Text | 해당 프로젝트의 최종 책임자 | 김OO (원장님), 홍길동 (업체 A) | 책임 소재 명확화 |
| **시작일 (Start Date)** | Date | 프로젝트 착수일 | 2024-05-01 | 일정 추적 기준 |
| **예상 완료일** | Date | 프로젝트 예상 마감일 | 2024-05-31 | 목표 설정 기준 |
| **최종 완료일** | Date | 프로젝트 실제 완료일 | N/A (진행 중 시 비워둠) | 완료 후 기록 |
| **현재 상태 상세** | Long Text | 프로젝트의 현재까지의 진행 상황 및 핵심 이슈 요약 | 인테리어 업체 3곳 견적 비교 중. A업체는 자재 사양 불일치 발생. | 상세 메모 |
| **다음 액션 아이템 (Next Action)** | Long Text | 다음 단계에서 반드시 수행해야 할 구체적인 행동 | A업체에 추가 자재 리스트 요청 및 미팅 일정 확정. | 실행 가능한 지시사항 |
| **관련 자료 링크** | URL | 관련 문서, 견적서, 미팅 기록 등의 외부 링크 | [링크 삽입] | 증빙 자료 보관 |

## 3. 매니저 운영 가이드라인 (Manager Operation Guide)

이 데이터 구조를 활용하여 프로젝트 관리 시스템을 구축하는 방법입니다.

1.  **중앙 허브 설정:** 모든 프로젝트 기록은 하나의 통합된 스프레드시트(Google Sheets, Excel) 또는 전용 PM 툴에 입력합니다.
2.  **상태 기반 필터링:** '상태 (Status)' 필드를 기준으로 데이터를 필터링하여 현재 진행 중인 업무 목록을 즉시 파악합니다. (예: `Status = "진행 중"`)
3.  **액션 아이템 우선순위 지정:** 매일 또는 매주, 각 프로젝트의 **'다음 액션 아이템'** 열만 따로 모아 **오늘/이번 주에
